# Reducible: Introduction to Graph Theory, A Computer Science Perspective (LFKZLXVO-Dg)

## Arc
Plain-language definition (0:00), roadmap (1:06), then a long "why care" section (1:22 to 4:30) with maps, social networks and Sudoku. Only then a formal definition (4:30), a terminology tour (5:20 to 9:56), graph types, three data-structure representations (10:14), a list of open problems (12:35), and a recap. It ends by teasing future algorithm videos.

## Strongest moves
1. **Motivate before define (1:22).** About three minutes of applications come before any set notation (4:47). The viewer knows why before learning what.
2. **Unexpected application (2:50).** Two expected uses (maps, friends), then Sudoku as a coloring graph, with the narrator saying viewers did not see it coming.
3. **Minimal definition, then names (0:00 to 0:48).** Circles and lines first; "vertices" and "edges" arrive after.
4. **Choose a tool and say why (12:00).** The adjacency list is picked because real graphs are sparse, with the social-network scale argument. This matches principle 13.
5. **End on a hard problem (14:33).** Visiting every vertex once has no known efficient algorithm; the narrator jokes about awards. That leaves a hook for the series.

## Unusual
There is no discovery, no brute force and no practice: the video is a guided tour. The vocabulary run (5:20 to 9:56) is a rule-list with one picture per term, and the only pause is the tree check (9:56), which the narrator calls satisfying. Terms come fast, around 15 in about four minutes, which is the weakest part for novices; there is no recall check.

## Principle verdicts
Confirmed: 1, 11, 12. Contradicted: 7 (terms are told). Partly: 2, 4, 8, 9, 10, 13. Not observed: 3, 5, 6. For 8, idea rate is uneven: dense in vocabulary and longer in motivation and the sparsity argument; there are no speech-rate data.

## Velocity implications
- Open with a familiar scene that morphs into the abstract model.
- Cap new terms per minute; tie each to a highlighted part of one running graph.
- Always attach a "why this one" reason to a representation choice.
- Learner model should schedule recall checks for introduced vocabulary.
- End units with a surprising open question as the teaser.
